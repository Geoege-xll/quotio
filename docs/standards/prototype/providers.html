Page design and interaction contract

页面目的与布局

直接将仪表盘 providerSection 的同一条 FlowLayout 移到此页顶部：已连接提供商为账号数标签，紧跟未连接且 supportsLocalProxySetup 的添加按钮。常规窗口单行，窄窗口自然换行；没有总体计数、额外添加标题或帮助说明。下方保持你的账号 → 自定义提供商。原型仅展示迁移区域和必要上下文，不重新设计完整 OAuth、文件导入、账号或自定义提供商编辑器。

页面导航

侧边栏在两个固定页面之间导航；其它侧边栏文字是现有页面的背景定位，不提供伪导航。演示条、构造数据与契约不进入生产。

交互

  • theme：选择浅色或深色，立即切换两套语义色阶；仅原型演示控件。
  • nav-dashboard：打开仪表盘原型 dashboard.html。
  • nav-providers：打开提供商原型 providers.html。
  • provider-scenario：切换已有账号、空账号、CPA 停止及授权失败演示；连接标签和未连接添加按钮与账号列表同步；空账号时八项均为添加按钮。
  • add-claude：仅在该提供商未连接时显示，演示现有 Claude Code OAuth 入口；代理停止时提示先启动，提供进行中和结果反馈，不访问真实账号或文件。
  • add-codex：仅在该提供商未连接时显示，演示现有 Codex OAuth 入口；代理停止时提示先启动，提供进行中和结果反馈，不访问真实账号或文件。
  • add-qwen：仅在该提供商未连接时显示，演示现有 Qwen Code OAuth 入口；代理停止时提示先启动，提供进行中和结果反馈，不访问真实账号或文件。
  • add-iflow：仅在该提供商未连接时显示，演示现有 iFlow OAuth 入口；代理停止时提示先启动，提供进行中和结果反馈，不访问真实账号或文件。
  • add-antigravity：仅在该提供商未连接时显示，演示现有 Antigravity OAuth 入口；代理停止时提示先启动，提供进行中和结果反馈，不访问真实账号或文件。
  • add-vertex：仅在该提供商未连接时显示，演示现有 Vertex AI JSON 文件导入 入口；代理停止时提示先启动，提供进行中和结果反馈，不访问真实账号或文件。
  • add-kiro：仅在该提供商未连接时显示，演示现有 Kiro OAuth 入口；代理停止时提示先启动，提供进行中和结果反馈，不访问真实账号或文件。
  • add-copilot：仅在该提供商未连接时显示，演示现有 GitHub Copilot OAuth 入口；代理停止时提示先启动，提供进行中和结果反馈，不访问真实账号或文件。
  • action-cancel：取消当前演示授权/导入，恢复可操作状态。
  • action-retry：在失败提示后重试同一演示操作。
  • account-toggle：切换示例账号启用/禁用状态并同步就绪计数，不改变账号总数。

状态与适配

默认同一行先显示 Claude Code 2、Codex 2、Antigravity 1 三个标签，再显示 Qwen Code、iFlow、Vertex AI、Kiro、GitHub Copilot 添加按钮；示例账号可禁用且就绪计数同步。空账号状态清空连接标签和账号列表，在同一个流式容器显示全部八项添加按钮。已连接提供商不重复出现添加按钮。CPA 停止时显示现有代理前置提示。仅在操作发生时展开反馈区，授权与导入展示进行中、完成、失败和取消；结果为原型内演示提示，不创建真实账号。 所有状态使用文字而非仅颜色；键盘 Tab 可到达控件，焦点环可见。窄窗口侧栏折为顶栏，提供商按钮与账号操作自然换行，账号名称保持可读。浅深色均使用系统字体，支持文本缩放和减少动态效果。

例外与边界

无特殊规范例外。页面完全离线，所有数字、账号和状态均为明确构造的演示数据；不访问真实 API、文件或凭据。本地添加项严格依据当前 supportsManualAuth && !isQuotaTrackingOnly：Claude Code、Codex、Qwen Code、iFlow、Antigravity、Vertex AI、Kiro、GitHub Copilot。Vertex 走导入，其余沿用原 OAuth 分支，不添加 Gemini 或 API Key 提供商。监控模式、真实账号管理与代理副作用沿用生产既有逻辑，不由原型重新定义。
