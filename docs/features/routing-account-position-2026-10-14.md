# 固定右侧账号卡片与光流连线匹配

## 问题与修复

此前 `stageEvents` 将新采集活动放在前面，`activeTargets` 直接按该顺序显示账号卡片。因此 A→B→A 串行轮询时，右侧顺序会变成 A/B、B/A、A/B，最新执行始终占第一行，光流在视觉上总沿同一条曲线移动。

本轮保留最新活动优先进入最多三个可见账号的逻辑，只在入选后按稳定账号身份排序。相同可见账号集合内的卡片顺序与位置不随轮询变化；空历史待命态也按稳定身份排序。显示名称、隐私遮罩和执行状态不参与排序。

光流继续按执行记录的 `targetID` 查对应账号的实际锚点；节点状态与执行明细仍使用真实记录。没有缓存账号对象或几何坐标，也没有修改 CPA、账本查询、动画时间、并发上限或现有布局。

## 必要验证

只运行 `RoutingAccountPositionTests` 中的一项原生窗口回归，没有运行全量测试：

1. 在生产 `RoutingStageView` 上恢复两个账号的历史，再连续发布 A→B→A 三次新执行。
2. 每次从实际节点的锚点偏好测量两个卡片的完整边界，断言位置和顺序保持不变。
3. 断言活动身份对应实际执行账号，生产曲线终点匹配该账号行边缘。
4. 将同一生产舞台的实测锚点传给生产光流绘制器，检查三个批次的去程与回程共六个中途帧，在预期光点附近对比静态基线像素。
5. 断言明细仍显示最新执行，不以固定卡片顺序重排执行列表。

全部数据为隔离夹具，未启动、停止或重启实际 CPA，也未消费实际队列。测试结果为 1 项通过、0 失败、0 跳过。
