# 并行升级交叉审计的八项修复

## 范围与归属

本轮修复账号新增、额度展示与 Claude 目录迁移之间已确认的八项问题，保留其他 agent 的账号布局、客户端卡片、路由节点与光流。直接在 master 工作，不发布、不安装，也不修改用户真实账号或客户端配置。

原 `AgentSetupViewModel` 继续持有草稿、目录、请求世代和 Task；原配置 actor 持有备份与文件事务。账号变更仍由原 `QuotaViewModel` 执行，连接表单状态仍由各自 Sheet 持有，额度获取器和刷新槽位不迁移。没有新增后台轮询或额度消费者。

## 八项行为

1. **1M 只接受明确声明**：`AgentConfiguration.is1MSupported` 保留签名，只识别末尾 `[1m]`，不再按 128k、-1m、:1m 或 1000k 等型号名称推断能力。角色已有布尔选择优先，旧 `false` 不变；原明确开启与编码回填规则保留。
2. **提供商必须有模型注册**：DeepSeek／Kimi／MiniMax 专用弹窗增加实时读取和手填映射，非空映射才可保存。`CustomProviderService.fetchProviderModels` 复用原模型 HTTP 传输，严格解析目录；连接测试的宽松成功条件仍独立。刷新仅追加新身份，保留已有 UUID、别名、预算、旧型号及连接其他字段，不注入静态型号。结果沿用 v8 的 `openai-compatibility.models` 补丁。
3. **关闭页也同步失效目录**：账号变更确认后立即推进原请求世代，不等下一次后台同步开始。`ClaudeCatalogCommitAuthorization` 与原配置 actor 同文件维护；原 VM 持有单次许可，世代变化同步撤销。actor 实际执行时在同一同步锁内校验许可并完成最新读取、备份和原子提交，覆盖“旧网络结果已返回、提交仍在 actor 排队”的窗口。锁内没有网络或 await；已开始的本地事务完整结束，不能在事务中间取消。
4. **角色链使用最终请求 ID**：统一计划在同一原角色图上解析全部目标，再统一写入其纯值配置。JSON、Shell、预览及说明消费同一最终映射；内层 1M 继续向上传递，循环仍阻止提交。顶层 Default／子代理的角色继承选择器继续保留，自定义名称与歧义绑定按最终模型保留。
5. **删除账号也刷新模型**：删除成功且原账号、模式、客户端与运行会话校验通过后，复用启停账号的目录失效及同步桥接。原删除提交、禁用偏好清理、本地重扫和账号目录刷新顺序保留；旧表单选值继续保留并标记未确认。
6. **连接测试隔离**：两个 Sheet 用 `BusinessModules/Accounts/Models/ProviderConnectionTestState` 共用纯值提交规则，状态仍是原 Sheet 的 `@State`。输入变化和关闭立即失效；返回前核对请求 UUID 与当前密钥、节点，旧成功／失败不能覆盖新结果或释放新互斥。新增模型读取同样核对输入及请求身份。
7. **DeepSeek 独立币种**：遍历 CNY／USD 桶，指标 ID 含币种且排序稳定，零余额仍显示，不跨币种求和。充值／赠金明细沿用原展示语义，账号规范键与固定账号选择不变。
8. **冷却按到期时间投影**：`AuthFileCooldown` 优先解析 `retry_at`，旧接口缺失或格式无法解析时，使用本次读取时间与 `remaining_seconds` 形成到期观测。该观测不写入编码协议。账号值、行和汇总共用纯投影；有冷却数据的可见行和横幅用 `TimelineView` 更新展示，不触发目录或额度刷新。到期后冷却徽章、重置按钮和汇总计数自动退出。
