## 共同修复原则

缺失或非法数值保留为未知，不转换成 0% 或 100%。界面在未知情况下不绘制伪造进度。
多个独立额度池取最低有效剩余量用于风险提示，不以平均值掩盖即将耗尽的额度池。
金额、无限额状态和独立余额不参与普通百分比最小值计算。
缓存展示必须说明快照时间及失败或过期状态，不把旧快照伪装成刚获取的数据。
GLM 内部账号标识不含 API Key；可读名称只用于显示，不承担密钥定位职责。

## 独立审计问题的修复落盘说明

1. Codex 重置券：通过同一 CPA 凭据索引补取库存，与原生路径复用库存解析器和分析合并逻辑。库存或 profile 的附加查询失败不推翻成功的主配额。
2. 同邮箱多凭据：Claude、Antigravity 等代理账号改用文件名与凭据索引组合键；额度和订阅统一使用该键。可读账号名与内部身份分离，旧邮箱选择仅在一对一匹配时兼容，存在歧义时不猜测。
3. 运行时凭据：认证列表保留白名单路由元数据，兼容字符串或数字凭据索引。查询优先使用列表数据，仅在缺少路由字段时尝试下载；下载失败不再无条件阻断查询。缺少必要项目时，Antigravity 可尝试从订阅接口发现项目。
4. Codex 窗口完整性：无名附加额度按来源位置生成标识；标准、Spark、附加与代码审查窗口共享 ID 冲突处理，不再因周期相同而删除独立窗口。无名项顺序改变时，其位置标识可能变化。
5. Antigravity 套餐：补取 `loadCodeAssist`，有效 `paidTier` 优先于 `currentTier`，兼容缺失描述及项目对象。快照携带订阅信息并在 VM 同步；附加查询没有得到套餐时移除陈旧展示，主额度仍可保留。

同时补充 Claude profile 套餐识别、Grok 的 xAI 提供方别名和列表用户路由元数据；Kiro 错误行改为未知额度，避免按 0% 耗尽处理。

以上实现已通过本轮编译与全量回归。补充的固定响应测试覆盖运行时元数据、同邮箱身份区分、重置券库存、辅助接口失败隔离、项目发现及独立窗口保留；仍不能以此代替实账号发布验收。

## 用量统计影响

源码审计显示，客户端用量引擎和代理用量统计各自使用独立账本：

- `Quotio/ClientUsage/ledger-v1.json` 保存客户端用量。
- `Quotio/UsageStatistics/ledger-v1.json` 保存代理用量，数据来自 `/usage-queue` 或 `/usage`。

配额模型和配额窗口解析不作为上述账本的输入。本轮不清空、不重算、不迁移历史用量。
Codex 配额卡片上的套餐分析、重置券信息与请求用量账本不是同一条数据链路；前者本轮已补齐读取路径，不能以账本独立为理由忽略展示回归。
