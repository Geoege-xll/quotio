# 统计内存优化与存储维护

日期：2026-09-08。承接 [运行内存检测](runtime-memory-audit-2026-09-08.md)；继续使用统一 SQLite，不新增另一套持久化框架。

## 本次完成的改造

原实现虽然已把持久化统一到 SQLite，仍会在内存中恢复完整账本和全部文件检查点。检测时 664,421 条用量记录、两层 Codex 检查点及字符串占据主要堆空间。此次调整数据读取与计算路径，保留原有统计口径和历史事实。

1. **展示只持有汇总。** 新增 `ClientUsageDisplaySnapshot`，只携带来源状态、采集时间、日／来源／模型汇总及 Pi 推理明细未知日期。`ClientUsageEngine` 不再缓存完整账本；页面模型不再持有历史记录、Codex 检查点数组。显式原始读取仅保留给兼容测试和诊断，生产展示使用 `loadPresentation`。
2. **汇总持久化并按变化日期更新。** 记录增删改时标记受影响日期，查询时只重建这些日期。没有事件变化时读取小型汇总表，筛选在现有摘要上完成。首次升级或日历／时区改变时重建；日边界使用 `Calendar`，保留夏令时和本地日期语义。
3. **扫描只返回本轮增量。** Claude／Pi 按日志追加读取，Codex 只恢复文件水位与必要元信息；已保存检查点留在 SQL 中。OpenCode 逐条查询已有修订，分批保存变化消息。每个扫描器完成后释放文件级临时数组，不再缓存所有历史文件的完整内容。
4. **Codex 按受影响会话投影。** 持久化待处理 scope 与会话队列，单次只加载目标会话和必要父会话。迟到父检查点仍可修正子会话差额，事务提交后才确认消费；中断后可以恢复已扫描而尚未入账的事件。首次升级建立队列和投影状态，后续无变化刷新不再重复计算所有会话。
5. **维护操作与采集共用生命周期屏障。** 应用层持有唯一维护协调器，切换设置页面或语言不会创建第二把锁。暂停并等待客户端扫描退出；CPA 先等待正在返回的已消费批次落盘，再暂停循环。操作完成后恢复当前页面和代理的采集意图。多模块清理即使某个模块重载失败，也会完成其余模块失效，防止已删除统计从旧缓存重新显示。

调用分析继续读取 SQL 日摘要，保留来源指纹跳扫和筛选复用。其变化来源仍按来源重建摘要，本次没有将它宣称为逐文件追加扫描。此前堆检测的主要占用来自客户端用量，因此没有扩大修改调用统计口径。

## 清理入口与行为

入口：**设置 → 诊断与维护 → 维护入口 → 存储与数据**。页面沿用原生分组 Form、Section、系统确认和已有设置页背景；维护搜索关键词包含存储、数据和缓存。

| 操作 | 行为 | 保留内容 |
| --- | --- | --- |
| 刷新存储概况 | 查询数据库／WAL 大小和三个模块的记录或摘要行数 | 不改变事实 |
| 清理缓存 | 释放统计报表、账本可重建内存、图片缓存及 URLCache | 历史事实、扫描水位、待处理扫描输入、价格及配置 |
| 回收数据库空闲空间 | 在暂停统计期间执行 SQLite `VACUUM` 和 WAL checkpoint | 全部统计和配置；不会直接删除 WAL 或数据库文件 |
| 清除所选统计数据 | 可分别选择仪表盘、用量统计、调用分析；同一事务清除所选事实、索引和扫描进度 | 未选模块、账户、代理／客户端配置、模型价格、客户端源日志 |

默认不勾选任何数据模块；删除必须经过系统确认，确认时冻结本轮选择。删除后先失效界面，再重新读取，若重读失败会明确提示“数据已清除，但页面刷新失败”。数据库未提交的失败保留原有事实。

清理统计后，仍存在的客户端源日志会在后续采集时重新导入；源日志已经消失的历史无法恢复。此轮采用这个默认行为，没有实现“忽略以前所有日志、从现在开始”的截止水位。迁移墓碑保留，防止已经废弃的 JSON 归档自动把旧统计重新导入。磁盘文件删除数据后不一定立即变小，需要另行选择回收空闲空间。

本次开发和验证没有对用户生产数据库执行清理，也没有删除客户端日志。

## 真实历史隔离基准

通过 SQLite 在线备份 API 从只读生产连接生成临时副本。所有迁移、恢复和验证写入只发生在副本中；源日志未参与此项性能测量。

测试环境：本机 arm64 Mac mini，macOS 26.5.2，Debug XCTest 宿主。内存由 `task_info(TASK_VM_INFO)` 读取 physical footprint 和宿主启动以来峰值，单位 MiB = 1,048,576 字节。

| 指标 | 实测 |
| --- | ---: |
| 备份时已入账记录 | 664,421 条 |
| 初始日／来源／模型汇总 | 133 组 |
| 读取前测试宿主 footprint | 25.11 MiB |
| 首次汇总读取耗时 | 4.198 秒 |
| 首次汇总读取后 footprint | 37.28 MiB，增加 12.17 MiB |
| 连续读取 20 次汇总 | 合计 3.982 毫秒 |
| 20 次读取后 footprint | 37.30 MiB，较首次仅增加 16 KiB |
| 首次升级恢复与会话投影 | 45.060 秒 |
| 投影后 footprint | 54.64 MiB |
| 后续 3 次无变化合并 | 合计 3.734 毫秒 |
| 全部校验结束后 footprint | 61.06 MiB |
| 测试宿主启动以来 footprint 峰值 | 120.45 MiB |

首次汇总读取包含建表／索引准备及首次聚合，不等于完整应用启动耗时。首次升级投影是在此历史规模下的一次性成本，可由持久化待处理队列中断恢复。无变化合并耗时只覆盖账本合并，不包括遍历源日志目录和文件探针。

备份时扫描表比已入账记录更新，因此恢复后新增 79 条待处理记录。验收逐列比较副本原先的 664,421 条事实，**变化或丢失为 0 条**；79 条新增记录均有副本原有扫描检查点支撑，投影队列已消费完毕。此后重复无变化合并的汇总保持一致。不能要求恢复后的总数与恢复前完全相同，否则会错误丢弃这批已扫描历史。

此前运行中的旧 Debug 应用 footprint 约 1.0 GiB、峰值约 3.1 GiB；该应用没有被本轮替换或重启。以上 37.28／61.06 MiB 是隔离测试宿主读写统计的结果，不能作为完整新应用长期运行内存，也不能据此声称已经验证了数小时使用曲线。新产物实际界面和长期运行仍由后续使用验证。

## 回归与证据

Debug 构建成功，整合回归 **178 项通过、0 失败、0 跳过**。覆盖：

- 新增汇总与增量扫描、重复事件、追加／截断／替换、Codex 父子会话与迟到修正、Pi 未知推理状态、夏令时日边界。

- 三模块清理范围、价格与迁移墓碑保留、事务回滚、缓存保留事实、磁盘整理。
- 清理期间进入／离开页面、取消的日历重建、CPA 已消费响应正常返回、多模块删除后单模块重载故障。

大规模手动基准单独运行 **1 项通过**，普通测试未显式提供隔离目录时自动跳过。实现位于 `QuotioTests/ClientUsageMemoryBenchmarkTests.swift`，要求临时路径前缀 `/tmp/quotio-memory-benchmark-`，不会自动读取生产数据库。
