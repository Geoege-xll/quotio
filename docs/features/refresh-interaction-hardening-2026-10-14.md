# 统计与账号刷新交互修正（2026-10-14）

## 用量统计

原导航刷新按钮绑定 `UsageStatisticsStore.isRefreshing`，因此 CPA 每两秒后台采集时，
按钮也会切换为进度圈并暂时禁用。现在改用独立 `ManualRefreshState`：只有用户点击才显示加载，
后台采集继续正常工作，图标及进度圈使用固定 18pt 占位，避免工具栏跳动。

用户点击时若唯一消费者正在采集，`refreshForUser` 等待当前批次落盘，不额外弹出队列。
结束后通过报表模型 `refreshRevision` 立即重读本地 SQL；筛选、图例、滚动位置和已有图表保持。
报表值类型补充完整 Equatable，内容相同的后台报表不重复发布，真实数据变化仍照常更新。
底部采集时间显示到分钟，服务内部仍保存完整时间精度。

## 账号管理

原“按服务商刷新”与“全量刷新”两个工具栏项合为一个原生 `AccountRefreshMenu`。
直接点击执行全量，下拉菜单提供“刷新全部”和当前筛选范围内的服务商。
不支持或正在刷新的服务商仍禁用，重复手动点击合并，后台刷新不驱动导航进度圈。
目录更新、全部额度、监控模式协调器，以及 Grok／Devin 补充刷新路径保留。

等待放在实际额度批次预约处：用户全量刷新读取目录期间若后台抢占提供商槽位，
`QuotaRefreshAvailability` 会等待冲突释放并预约，再执行刷新；取消后不预约。
后台普通轮询保持原有遇冲突合并跳过策略，不因手动等待产生第二份并发批次。

监控模式侧栏的通用刷新在已经提供页面刷新入口的仪表盘、统计和账号页面隐藏；
旧 quota 与 providers 路由使用同一规则。CPA 模式的启动／停止按钮保留。
