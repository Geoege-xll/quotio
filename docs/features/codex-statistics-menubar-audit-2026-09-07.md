# Codex 统计失败与菜单栏同步审计

日期：2026-09-07。
参考：本地 `/tmp/quotio-aiusage-reference`，AIUsage 提交 `bdb83bbe077879855c03e656cbc2fe5890bd27e9`。
本轮只读比较上游代码、项目实现及本机日志的事件结构；没有运行修改后的代码、构建或测试。

## 实际证据

- 本机 Codex sessions/archived_sessions 枚举到 1,302 个 JSONL 文件，总大小 6,663,121,714 字节，枚举未发现读取权限错误。
- 有界抽样的两个较大文件中，各自前 64 MiB 已发现 5 行超过 4 MiB 的 compacted 正文，最大完整行 5,526,915 字节。
- 已保存的调用统计摘要中，Codex 状态为 read_failed，filesScanned/eventCount 为零；这与调用读取器遇到大行后抛错、引擎丢弃本来源当次结果的路径一致。
- 近期日志大量使用 response_item/custom_tool_call，字段为 call_id、name、input；原解析器只消费 function_call/arguments，漏掉这些工具调用。
- fork 文件首条 session_meta 带 forked_from_id，后面包含继承父历史中的另一条 session_meta。原用量解析把后者标为身份冲突，并覆盖 parent/forkDate。
- 未读取或输出会话正文、工具参数、账号凭据和原始会话标识到审计文档；结构检查只输出字段名、事件类型、大小及计数。

## 上游与本项目的区别

AIUsage 的调用读取器保留每行前 256 KiB，用量读取器保留前 1 MiB，并对前缀做字段搜索。它不会因为超长行报告整来源失败，但可能静默丢失头部以外信息，正文中的同名字段也不能作为可靠的结构化事件证据。

本项目移植后改为完整 JSON 解码，并添加了 4 MiB 安全上限，却把所有超长行都计为读取错误。对并不参与统计的 compacted/图片/工具输出行，这会制造错误状态。不能将本机的 read_failed 简单归咎于上游，也不能照搬上游的静默截断。

## 本轮修改

### Codex 扫描

- 共用有偏移、大小快照和取消支持的有界读取器，按顶层类型及直接 payload 类型过滤无关事件。
- 无关大正文跳过，不计为统计读取失败；相关事件仍要求完整 JSON，相关大行或坏文件保留不完整标记。
- 调用扫描按文件隔离错误，保留其它文件的有效结果，不因单文件故障把整个来源变成零调用。
- 同时支持 function_call 与 custom_tool_call，按 call_id 去重，并支持 input 参数字段。
- fork 会话以第一条有效 session_meta 为身份依据，后续继承头不能清除父关系或制造冲突。
- Codex 文件缓存升级至 v2。v1 的可用历史检查点仍保留，但现存源文件需要重扫；有错误的缓存不再无条件长期复用。

### 菜单栏

- 状态栏统一调用 QuotaViewModel 的菜单栏数据投影，删除 AppBootstrap 内重复的账号解析和聚合实现。
- providerQuotas 的内部值变化也触发合并通知，不再仅依赖供应商字典数量、窗口事件或部分显式刷新通知。
- 配额页供应商摘要与状态栏共用聚合入口，排除独立金额/积分指标，统一未知值与百分比边界，保留既有聚合偏好。
- 双行 Codex 主额度不混入 Spark 附加限额；Claude 主周额度不混入 Sonnet/Opus 独立限额。独立限额仍在菜单明细保留。
- 菜单明细使用额度桶原始 ID，避免不同桶同名时被 SwiftUI 合并。
- 菜单百分比与配额页统一四舍五入和未知值显示。

### 用量统计界面

刷新/取消用量按钮移入导航工具栏；原有来源与日期过滤行为不变。

## 保留边界

- 没有删除真实统计账本、缓存目录或账号凭据。首次升级刷新需要重新读取旧索引对应的源文件，不承诺大历史瞬时完成。
- 真正缺失父会话、相关事件损坏、权限故障仍可能显示读取不完整；不为了状态变绿而掩盖无法证明的数据。
- 现有调用历史是日聚合高水位，无法凭当前源码变更精确回退旧版已经计入的错误分类；本轮不擅自清空用户历史。
- 本轮未执行构建、回归测试或完整真实历史重扫，修改效果需要后续授权验证。
