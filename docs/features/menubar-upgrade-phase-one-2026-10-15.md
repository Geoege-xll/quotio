# 菜单栏第一批交互与布局升级

日期：2026-10-15。

## 范围与保留边界

吸收上游菜单栏“原位更新内容”和账号明细的信息层级，继续使用本项目原生 NSMenu、QuotaViewModel 和现有偏好。主窗口、账号管理、CPA 启停和自动刷新调度不变，没有引入 Rust 宿主、SPM 迁移、额度历史、预测或新的密度设置。

保留 `card`、`lowestBar`、`ring` 三种样式及已用／剩余口径；配置键、精确账号映射、刷新槽位和手动刷新合并规则不变。所有受保护状态仍由原宿主持有，没有开放 `private(set)` 或复制账号快照。

## 实现

- `App/MenuBar/StatusBarManager.swift`：每次打开时读取最新目录并装配菜单。跟踪期间不再移除、替换菜单项或子菜单；原通知入口只同步外观。状态栏位图在打开前按高亮外观绘制一次并保留原宽度，跟踪期间冻结绘制，关闭后用最新配置恢复自然宽度。账号增删、提供商分组及排序在下次打开时更新。
- `StatusBarMenuBuilder.swift`：用局部 `MenuLiveContent` 将读取延迟到 SwiftUI body，让 Observation 追踪原 VM 的额度、套餐、刷新和 IDE 使用状态。始终按提供商及精确账号键读取；账号移除后显示空状态，禁止复用打开时旧额度或按邮箱猜测。标题使用原尺寸桥接。
- `Views/MenuAccountCardView.swift`：缩小卡片内部及外部间距，长账号中间省略，套餐跟随账号。IDE 活动徽章及原切换按钮与更新时间放在底行，仍使用原回调和局部操作状态。刷新按钮继续调用原单账号入口。
- `Views/MenuQuotaLayouts.swift`：原三种布局只收紧间距；从父级传入同一只读设置实例，默认仍为 shared。未知值、金额、次数和已用／剩余格式化沿用原规则。
- `Views/MenuAccountDetailView.swift`：全部提供商统一向右展开当前账号的额度桶、重置信息和更新时间。单个动态原生项内采用最高 340pt 的滚动列表，模型多时仍可访问尾部；Antigravity 保留原始模型名及原排序规则。Codex 原分析作为下一层子菜单保留，迟到数据在原承载视图中显示。
- `Views/MenuBasicViews.swift`：标题加载使用项目已有 `SmallProgressView`，消除缩放 ProgressView 导致的浮点尺寸约束警告，加载判定不变。

没有新增网络请求、轮询、通知订阅或生产 Task 句柄。Debug 只读菜单夹具创建独立管理器，不创建状态栏图标、不注册共享动作宿主，不影响正在运行的 CPA。

## 定向验证

新增 `MenuBarUpgradeTests` 六项：

1. 真实 NSMenu 跟踪中开始／结束刷新、更新额度及新增账号，既有菜单项、承载视图和子菜单身份保持不变；最新额度实际绘制，新增账号在下次打开出现。
2. 全部提供商具有统一明细入口，Codex 嵌套分析入口保留，原生标题不存放邮箱。
3. 30 项额度在限定高度内滚动，尾部可达；账号移除后原视图不显示旧数值，重新打开后移除原生项。
4. 迟到 Codex 分析更新原嵌套承载视图。
5. 三种样式 × 两种显示口径真实渲染，金额和未知项保留，六种截图各异；菜单展开期间隐私切换更新原视图。
6. 长账号卡片通过隔离窗口内的真实鼠标事件触发原 IDE 按钮回调，不执行真实账号切换。

另定向验证原代理菜单状态两项、提供商原位筛选两项、账号排序两项、手动刷新与身份映射三项、CPA 首轮菜单同步一项，以及 Claude／Codex 配对额度两项。共 **18 个不同用例最终通过**，未执行全量测试。

验证过程保留原始记录：首轮因测试辅助功能协议名称与当前 SDK 不符而未运行；适配后，测试宿主没有 SwiftUI 辅助功能子树，四项渲染／点击用例失败。改为本地 Vision 截图识别和隔离鼠标事件后，小号彩色／环内数字仍存在识别漏字；已实际查看六种截图确认正确，并以六种截图差异验证样式和口径，精确额度更新另由真实菜单跟踪用例识别。随后六项新增测试全部通过；标题改用原轻量进度组件后，仅复跑相关跟踪用例通过，旧尺寸警告不再出现。

测试只使用临时偏好、空凭据目录和内存额度，关闭后台服务。截图识别在本地进行，无外部识别服务。真实跟踪覆盖根菜单；明细滚动和迟到分析使用独立窗口承载验证，没有执行真实用户账号的在线取数或替换已安装应用。彩色状态栏高亮按代码路径与原绘制实现复核，未连接测试管理器的真实状态栏图标。
