# 客户端用量统计：图表无响应修复

## 现场证据

用户提供的 2026-09-08 11:48:20–11:49:34 系统报告记录了 QuotioPlus 1.0.0（73）
持续 **73.96 秒**的 hang。报告实际采样 1.10 秒，主线程在此期间使用 CPU 1.000 秒，
进程 footprint 为 **202.95 MB**。

主线程采样持续位于 SwiftUI / AttributeGraph 的事务更新，包含 Charts 锚点测量及复制路径。
因此本次优先减少图表布局和高频状态更新；报告不足以确认某个单独 API 是唯一根因，
也没有给出异常崩溃或内存耗尽的证据。

## 修改

- 日趋势通过独立的可观察对象保存选中日期，同一日的重复选择直接去重。
  覆盖层和读数行观察选中值，父页面和静态图表不读取它。
- 移除系统日期选择与连续鼠标悬停同时写入状态的双路径；提示线改由覆盖层绘制，
  不再在悬停时向 ChartContent 插入或移除 RuleMark。
- 长历史趋势最多绘制 240 个真实数据点，每段保留峰谷，保留首尾日期并维持顺序。
  抽样只影响折线绘制，统计合计、悬停读数和逐日明细继续读取完整数据。
- 图表固定非负 Y 轴范围并屏蔽祖先动画，避免额外的轴域重算与锚点插值。
- 最多六项的模型圆环使用固定画布中的 Shape 绘制，比例标签独立定位，
  保留原模型分组、来源色和零值处理。图例为辅助功能提供精确数量及占比。
- 模型行小趋势使用 Canvas 绘制，每行最多 64 个真实点，减少多套 Charts 布局图。

未更改采集器、数据库、筛选口径或缓存行为，也未截断统计明细。

## 验证与边界

五组测试共 **17 项通过、0 失败**：

- `UsageTrendPlotDataTests`：10,000 日历史的数量上限、首尾与峰谷、原值及完整日期定位；空数据和短序列。
- `UsageStatisticsChartRenderingTests`：真实 NSHostingController / NSWindow 中切换数据、尺寸和滚动；
  1,095 日图表接收 80 组、共 80,000 次选择状态调用，完成耗时 **0.471 秒**。
- `UsageStatisticsDistributionTests`、`UsageStatisticsPresentationTests`：完整模型投影与展示统计的既有回归。
- `CPAUsageDetailLayoutTests`：此前价格统计与请求明细的窗口约束回归。

上述压力用例直接调用选择状态，没有发送 80,000 次真实鼠标事件。
普通滚动用例在旧版同样通过，因此不能将其视为对原 73.96 秒无响应的精确复现，
也不能据此计算现场卡死时长的改善比例。实际长时间使用与用户现场仍需继续验证。

验证使用合成数据，不读取用户用量数据库，不请求录屏权限。
独立只读评审未发现阻断项；精确数值的辅助功能读取及恰好 10% 标签边界两项细节已修正。

Release 的 arm64 / x86_64 通用构建通过，本地签名验证通过，修复包已替换至
`/Applications/QuotioPlus.app`，保留旧应用备份。版本仍为 1.0.0（73），本次未更新 GitHub 发布资产。
本机旧进程另有启动阶段的系统钥匙串授权等待，采样位于 `SecItemCopyMatching`；
这与用户报告的图表布局热区不同。新构建需完成 macOS 授权后才能验证实际用户数据页面。
