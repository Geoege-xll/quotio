# 路由中心数据与刷新加固（2026-10-14）

路由中心沿用拓扑舞台、最近执行解释和执行列表三张卡片，不增加导航或内部 Tab。
本次重点是让展示语义与 CPA v8 上报数据一致，保留既有账号、配置、历史账本和统计功能。

## 数据边界

- CPA 用量队列记录每次上游执行；一次入站请求可能有多次失败／成功尝试或附加模型计费事件。
- 路由页计数明确为“今日执行、取消、失败尝试”，不是入站请求数、改道数或 Agent 最终错误数。
- 最近执行说明仅陈述请求模型、可确认账号和 CPA 上报结果。不以当前策略、当前账号数或列表顺序解释历史选号。
- 成功／失败／取消均为上游执行结果。最近 12 秒的活动强调和短时动画不代表请求仍在执行；首次历史恢复不触发分发动画。
- 没有上下文容量证据时保留真实输入 Token，标为“容量未知”，不按模型家族猜测占用率。
- 缺失耗时、状态码和身份保留未知。标准 v8 队列会归一化部分状态码，明细称为“CPA 上报状态”，不声称厂商原始 HTTP 响应。

## v8 元数据与兼容

`CPAUsageContext` 新增可选的入站请求、trace、execution 和账号索引摘要，以及客户端分类、流式标记和响应模型。
原始请求 ID、trace ID、execution ID、账号索引和 User-Agent 不进入 SQLite 事件；客户端只保存有限产品分类。
API 密钥继续保存摘要及短标签，endpoint 继续只保留路径，错误正文和认证令牌不落盘。

新增字段保存在现有事件 payload 中，无需重建数据库。旧 Codable payload 缺少字段时继续解码为 nil；
既有事件 ID、日汇总、历史迁移和去重规则保持兼容。旧记录不会被补写成猜测的身份或生命周期。

账号匹配优先使用 `auth_index` 摘要且必须唯一；明确索引匹配失败时不退回同邮箱新账号。
没有索引的旧记录，仅在 provider 与 source 身份能唯一精确关联时显示账号，否则显示“账号未知”。
入口节点以完整密钥摘要和客户端分类分组，后四位仅展示，不参与去重。
所有账号身份复用现有隐私脱敏规则，待命、历史解释、执行明细均随隐私偏好更新。

## 共享查询与生命周期

`RoutingCenterView` 持有 `CPARoutingViewModel`，三个子组件只读同一份 `CPARoutingSnapshot`。
查询使用本地自然日零点到同一 `now`，一次计数聚合及索引限制的最近 15 条查询，省去原先三份完整查询和四类筛选目录。
旧日汇总无法重建执行明细，仍由原统计页面展示，不混入路由计数。

`UsageStatisticsStore` 仍是全应用唯一队列消费者；刷新路由页仅查询本地账本和读取配置，不弹队列、不保存配置。
当前策略和额外重试轮数独立读取 CPA getter，0 是有效配置；停止或读取失败展示未知。
管理客户端指针变化与运行状态都参与观察，空队列启停也会失效配置；旧会话的迟到结果不能回灌。

统计修订使用可取消的视图任务，模型进一步检查查询代次，较慢结果不能覆盖新版本。
成功空查询、跨日和清空统计会清除最近执行及暂停缓存。读取失败单独显示，不将旧记录当作有效新结果。
暂停只冻结列表；共享快照继续更新，恢复立即展示最后一批，无需等待新事件。
每 30 秒检查自然日是否变化，仅跨日时查询；窗口重新激活会刷新数据与配置。
待命节点直接派生自当前账号和客户端目录，避免配置变化后节点仍留在旧状态。

## 仍需真实追踪支持的内容

完整候选账号顺序、选择理由、入站请求开始／结束、客户端最终错误和准确改道次数仍需要实际请求追踪证据。
本轮保留 CPA 已有能力和管理协议，不引入独立路由后端，也不根据用量事件补造这些字段。
