# 运行内存检测：客户端用量全量历史常驻

检测日期：2026-09-08，约 09:03–09:07（Asia/Shanghai）。

## 结论

用户反馈使用一段时间后内存持续增长。本轮对现有运行进程进行只读内存检测，并核对对应数据加载链路。主要占用来自客户端用量的完整历史账本、Codex 扫描检查点及字符串。持久化已经统一到 SQLite，但读取和处理侧仍恢复完整内存快照，导致历史越多，常驻内存越大。

当前快照没有证明持续发生 GB 级失联内存泄漏：两次间隔约 103 秒的内存分区采样基本稳定，`leaks` 只检出 331 个分配、共 16,544 字节。这不排除其他时段或有引用环的增长，但不能用这部分小泄漏解释约 1 GB 常驻。

## 根因与代码位置

1. **完整账本长期常驻。** `ClientUsageEngine.load()` 调用 `loadLedger()`，将所有用量记录与账本检查点保存到 `cached`；`loadPresentation()` 又把含明细的快照传给视图模型。位置：`Quotio/Services/ClientUsage/ClientUsageEngine.swift:35`、`Quotio/Services/ClientUsage/ClientUsageSQLiteStore.swift:74`。
2. **扫描器再保留全部文件检查点。** `loadCodexCaches()` 为每个文件读取完整检查点数组，最终将整个字典保存到 `codexCaches`。实际堆中存在对应的检查点数组与文件缓存字典。位置：`Quotio/Services/ClientUsage/ClientUsageSQLiteScanStore.swift:143`。
3. **应用生命周期使大数据不随页面退出释放。** `QuotioApp` 持有 `ClientUsageViewModel`，离开用量页面只停止自动刷新；引擎与扫描器中的全量缓存继续存活。这原本用于避免切页重扫，代价是长期保留大数据。位置：`Quotio/QuotioApp.swift:173`、`Quotio/Views/Screens/UsageStatisticsScreen.swift:35`。
4. **刷新存在放大临时峰值的路径。** 每个来源完成后，`merge()` 都会遍历历史，构造记录字典与检查点字典。Codex 变更后还对全历史进行会话分组、去重、排序和投影，期间有旧快照、新数组及临时索引并存。位置：`Quotio/Services/ClientUsage/ClientUsageEngine.swift:97`、`Quotio/Services/ClientUsage/CodexClientUsageSource.swift:180`。这在源码上构成峰值风险；本轮未捕获 3.1 GiB 峰值发生时的分配堆栈，不能将峰值全部归因于某一行。

当前调用分析只保存 972 条日摘要，堆中占主导的是客户端用量类型，因此应优先改造用量数据流，而非先调整图表样式或更换数据库框架。

## 建议的改造顺序

1. **展示只返回汇总。** UI 与常驻引擎只保存日／来源／模型的统计桶、来源状态和少量筛选结果；完整明细留在数据库，按需分页读取。不能仅在退出页面时清空，然后下次进入再次加载 66 万条。
2. **扫描缓存仅常驻文件水位与摘要。** 按文件、按会话加载变更所需的检查点，以有界工作集处理后释放。保留数据库中的恢复信息，不能以丢弃历史换取低内存。
3. **Codex 按受影响会话增量重算。** 查询变化会话和其必要的父／子依赖，更新对应投影；保留分叉累计抵扣、迟到历史修正、重复事件去重和取消事务语义。避免每次某个文件增长就重新构造全历史字典和数组。
4. **维护可增量更新的统计汇总。** 写入事实时更新受影响的汇总；日期筛选读取小结果。统计时区／日历变化需要显式重建或按时区缓存，不能固定 UTC 日桶冒充本地日期。上述 17 秒全历史查询不能进入频繁 UI 路径。

这些属于数据读取和计算方式调整，继续使用现有 SQLite 即可。更换为 SwiftData，如果仍把全部记录加载并常驻，同样保留这类内存成本。

## 后续验收

- 保留此次生产历史规模，在隔离副本上测试，避免写入用户当前使用中的数据库。
- 分别测量冷启动、首次打开用量、无变化刷新、新增记录刷新、筛选切换和离开页面后的 footprint 及峰值。
- 连续重复刷新，确认无变化刷新后的常驻量稳定；新历史仅扩大数据库和必要摘要，不再要求全历史对象常驻。
- 对比新旧总量、日期边界、模型／来源汇总、Codex 父子会话和取消恢复结果，确保内存下降不导致统计丢失或重复。
- 对优化产物分别验证 Debug 和 Release。本轮没有运行改造后产物，因此没有“优化后节省多少内存”的实测结果。
