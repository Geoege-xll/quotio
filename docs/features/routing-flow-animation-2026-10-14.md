# 路由拓扑细线光流与慢请求适配

本轮只优化路由拓扑的连线与动效。当前策略、可用账号、故障转移、额外重试轮数四项卡片的代码与位置逐字保持；其余路由明细、暂停列表、刷新、配置与隐私功能沿用既有实现。

## 节点与光流

- 移除小猫、爪印、原有固定舞台中线及永久呼吸动画。
- 每个来源行、上游行分别提供 `bounds` 锚点；中枢锚点只包含 38pt 图标，不包含下方文字。在同一 `GeometryReader` 中解析边界，曲线从节点边缘外 2pt 接入中枢图标边缘。
- 静态曲线宽 1.15pt。活动时短光段与光点沿同一贝塞尔参数取样，避免曲线 trim 的弧长参数与光点位置不一致。
- 单次播放 1.8 秒：来源 → 中枢，中枢短暂交接，中枢 → 上游，上游结果 → 中枢。回程成功绿色、失败红色、取消橙色；节点仍保留文字终态。回程不推断客户端最终结果。
- `TimelineView` 最多 30fps，仅更新连线层。到期、服务停止、采集读取异常、场景不可见时停帧；减少动态效果时仅静态强调关联连线。节点的“最近活动”强调使用低频时钟，12 秒后结束。

## 慢请求与高频记录

动画表达的是“刚采集到的上游执行记录”，不表示实时在途请求。CPA 完成上游执行后才有记录，因此以本地查询完成后的到达时间开始播放，不能再用执行时间戳是否小于 12 秒作为动画门槛。

共享展示模型比较整批新记录 ID，不再只观察时间列表第一条。首次历史恢复、跨日恢复、读取失败后恢复同一记录不重播；成功清空后的新记录可以播放。较旧异步查询仍受原有修订号与取消保护。

生产 `routingSnapshot` 保留一次聚合和一次明细 SQL。在明细 SQL 内联合两个有界集合：按时间倒序的最新 15 条，以及按 SQLite `rowid` 入库顺序的近期 15 条。去重后最多 30 条候选用于判断新到达；时间列表仍为原有 15 条，按 `timestamp DESC,id DESC` 排序，今日计数仍统计所有今日记录。这样在已有超过 15 条较新执行时，迟到慢请求仍能提供舞台动效证据。

联合候选不是全日队列，不增加管理 API 消费者、数据库查询定时器、表字段或配置迁移。每批相同来源、上游、终态的动效合并，最多 3 条并发光流，最多保留 6 条短时活动。舞台优先展示最近采集的关联节点，列表不改变排序；缺失实际锚点的活动直接跳过，不能连到其他账号。

## 回归证据

在 macOS 原生窗口中使用生产 `Canvas` 与 `TimelineView` 验证，不启动真实 CPA，不读取真实认证文件或用户账本：

- 验证 580pt / 840pt 下三组来源与上游曲线端点，和实际偏好锚点随窗口缩放重新测量。
- 浅色、深色分别验证 0.18、0.42、0.86、1.08、1.35、1.62 秒中途帧，在理论光点附近对比基线像素，确认实际可见。
- 原生窗口显示后发布活动，在约 140ms / 380ms 捕获生产 `TimelineView` 帧，确认不同位置与可见光点；完成后图像回到静态基线。
- 同时验证成功、失败、取消三条返回路径均可见；减少动态效果和停止状态的两帧图像相同。
- 临时 SQLite 账本先入库 25 条较新执行，再入库时间早 180 秒的慢请求：时间列表保持不变、今日计数增加、迟到节点进入舞台、活动到达时钟正确、重复刷新不重播。
- 覆盖高频动效合并与数量上限、初次历史、跨日、清空、读取恢复、过期精度，以及既有刷新交互、采集状态、分析导航和维护生命周期回归。

验证结果：54 项测试通过，0 失败、0 跳过、无运行时警告；最终 Debug 构建成功。
