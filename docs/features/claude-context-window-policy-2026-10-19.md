# Claude Code 上下文声明与历史覆盖处理

## 业务归属与保留边界

本轮只调整客户端配置业务中的上下文声明，不修改模型目录、角色映射、逐模型 1M、账号容量或代理路由。原 `AgentConfiguration` 保存草稿，原 `AgentSetupViewModel` 持有页面状态、请求世代与 Task；原配置 actor 负责磁盘基线、备份、原子提交和回滚，原 `ShellProfileManager` 负责受管 Shell 段。不新增管理器、后台任务、配置键或模型容量表。

参考 CC Switch 4.0.15 的 `main` 提交 [`734c4831ddd311df2207a7948178375f8543898c`](https://github.com/farion1231/cc-switch/commit/734c4831ddd311df2207a7948178375f8543898c)：其提供商独立窗口、条件写入及切换清理可作为边界依据；其 Stack 聚合取非 1M 最小窗口需要各提供商的明确容量。当前 CPA 客户端目录只确认 ID，本轮不按型号、ID 后缀以外的名称特征或别家预设猜容量，也不移植 CC Switch 的专属路由编码。

## 默认与兼容

- 原 `claudeMaxContextTokens` 与 CodingKey 名称保留，值改为可选整数。`nil` 表示跟随 Claude Code，首次配置及缺失旧字段都不再注入 200K。
- 已有正整数继续作为明确的自定义窗口，包括 `200000`。旧程序写入和用户手填同值没有可靠归属证据，不能按值批量清理。
- JSON 读取兼容正整数字符串及整数值，回填和保存冲突检查共用同一私有解析规则。前导零、正号、首尾空白按等值整数处理；布尔、小数、非法串不冒充容量。
- 自定义尚未填写时，仅在当前草稿中暂存 0，校验阻止保存，不产生 0 或猜测的 200K。恢复官方配置不使用代理窗口，不因该未完成草稿被阻止。
- 模型自己的 `[1m]` 与全局覆盖独立。跟随 CLI 不表示目录已证明模型容量，未知 ID 仍由 CLI 原生规则处理。

## 配置写入与历史覆盖

1. 明确的正整数才写 `CLAUDE_CODE_MAX_CONTEXT_TOKENS`。跟随模式从本次最新 JSON 对象移除旧键；未知根字段和 env 继续局部合并，不重建整份配置。
2. Shell 跟随模式显式生成 `unset CLAUDE_CODE_MAX_CONTEXT_TOKENS`，覆盖执行本管理段前已经继承的旧 export。自定义模式生成明确 export，沿用原单引号保护。
3. 保存 JSON＋Shell 继续替换所有成对受管段；生产受管配置保存 JSON 时继续清理旧受管 Shell 段。修改前备份，管理段外命令保留，标记不完整则拒绝，失败沿用原 JSON 收据回滚。
4. 仅 Shell 无法移除或替换现有 JSON env 的优先覆盖。页面用原 savedConfig 提前校验，actor 最终以最新磁盘再核对；冲突时拒绝并提示选择 JSON 或 JSON＋Shell，不写文件、不产生备份。手动预览按有效 JSON 操作输出可用方案，并在可复制 Shell 上明确这条依赖，不被隐藏的自动 Shell-only 选项阻止；详见[系统重构](claude-configuration-system-refactor-2026-10-19.md)。
5. 独立的 `CLAUDE_CODE_AUTO_COMPACT_WINDOW`、输出上限及其他用户设置保持原样，本轮不将压缩阈值当成模型容量。后台已接管目录同步重新读取最新磁盘，保持 nil 或显式窗口，不重新补入 200K。

Shell 配置更新后需要新开终端让启动脚本重新生效；复制执行新生成的 Shell 段也会执行该 unset。应用不改写现有父终端进程的环境，不清理用户在受管段外自行定义的命令。

## 页面交互

高级区默认收起，沿用本页整行按钮展开方式；收起时显示跟随／自定义摘要与既有 1M 提示。展开后使用项目分段控件选择“跟随 Claude Code／自定义窗口”，仅自定义模式出现令牌输入框，不预填容量。

折叠状态仅由原视图持有，模式直接由原配置字段推导，不复制业务状态。切回跟随时原生输入框的迟到结束编辑回调必须被拒绝，不能将 nil 回写为 0 并重新开启自定义。模型菜单预览已成为模型槽与高级参数之间的独立卡片，沿用原组件自身的折叠和补全／面板分段状态；展开预览不要求展开高级区。普通应用、手动预览及原有压缩功能保留；新增说明具有全部四种应用语言资源。
