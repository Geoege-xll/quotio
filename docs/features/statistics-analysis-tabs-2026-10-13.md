# 统计分析统一入口与导航 Tab

## 页面职责

- 侧边栏只提供「统计分析」一个入口，监控模式与本地代理模式均可进入。
- 系统导航栏使用原生分段选择器切换「用量统计」与「调用分析」。首次进入默认 CPA 用量，之后记住上次选择。
- 用量统计读取 CPA 已持久化的账本，展示统一筛选、四项主指标、Token／缓存／请求结果／性能、趋势、分布与请求下钻。
- 请求明细与价格页面从用量 Tab 打开，继承进入时的筛选快照。
- 本地客户端 Token 历史通过导航栏「客户端用量」辅助入口打开，与 CPA 保持独立账本。
- 仪表盘保留运行卡、今日请求／Token／成功率／平均延迟以及「查看统计分析」跳转。旧 CPA 只有进程累计值时使用通用标题，不能把累计值标成今日。

## 状态与生命周期

`ContentView` 持有 `AnalyticsNavigationState`，保留 Tab、CPA 筛选及图表查询模型。仪表盘跳转选择 CPA Tab，不覆盖统计页原来的筛选。

两个 Tab 使用稳定的 `ZStack`，通过透明度、交互与辅助功能可见性切换；原生滚动容器、来源／日期筛选、MCP 展开状态和图表图例不会因切换被销毁。CPA 的查询任务同时检查 Tab、导航路径和窗口活跃状态，隐藏时停止 SQL 轮询。

本地采集由页面显式调用 `setPageActive`：进入调用 Tab 或客户端辅助页面时检查新鲜度并扫描，切出／返回／离开统计页面时取消。已发布的摘要和已保存历史保留，取消代际拒绝迟到结果。离页还结束未完成来源的进度阶段，避免新鲜快照重入时无任务却继续显示「扫描中」。维护期间进入后再离开，维护完成不恢复隐藏页面的扫描。

调用分析的正常来源与采集细节默认折叠，错误提示保持可见。CPA 的后台采集继续由应用和代理生命周期驱动，全应用只有一个消费式队列读取者，各页面仅查询本地索引。

## 验证

- 导航偏好使用独立 UserDefaults 域，测试默认 CPA、未知偏好回退、Tab 恢复、仪表盘跳转保留筛选、两种模式的单一入口。
- 客户端与调用生命周期使用临时日志和账本，测试可见性启动／取消、新鲜快照重入、维护延迟刷新及已完成来源保留。
- 原生窗口测试使用隔离 CPA 夹具和空客户端目录，检查两份纵向滚动容器的对象身份与滚动偏移，并生成浅色／深色预览。
- 回归继续覆盖 CPA 历史查询、趋势与展示口径；不连接真实代理，不读取真实会话日志。
