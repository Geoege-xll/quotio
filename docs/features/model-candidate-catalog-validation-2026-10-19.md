# 当前服务模型候选、别名核对与账号变更联动

> 后续行为：Claude 生效菜单的统一清理、归档和备份事务已由[目录菜单统一迁移](claude-catalog-migration-2026-10-19.md)接替；本页的“旧值继续留在菜单”属于该次候选修复的历史边界。

## 业务归属与保留边界

本轮补齐动态目录在配置选择器与账号操作之间的行为，沿用现有业务分类，不按行数拆分文件。

- `BusinessModules/AgentConfiguration/Models/AgentModelCandidatePolicy.swift` 是配置页专用的无状态投影，区分实际候选、别名元数据、原生角色与当前草稿。它不访问账号、不发请求、不持有 Task 或缓存。
- `AgentSetupViewModel` 继续持有原目录、来源证据、加载状态、请求世代与配置会话。选择器读取与当前客户端、页面、URL 和客户端 key 匹配的成功结果；切换来源后，旧数组不能继续作为可用性证据。
- `QuotaViewModel` 继续持有原配置 VM 和仪表盘目录。账号联动只传递本次操作的瞬时令牌，不创建懒加载 VM、不新增状态或 Task。`modelCatalog` 的受保护写入留在主类，原 `private(set)` 保持不变。
- OAuth 启停继续在原账号变更扩展执行；API Key 连接继续在账号页面原配置同步任务内执行。原账号持久化、刷新、v8 同步和配置文件写入事务各归其原宿主。

## 候选与旧配置规则

1. 普通候选只来自当前服务返回的请求 `id`，不会用展示 `name`、提供商名称、旧选择或静态型号补充目录。保留原 Copilot 候选筛选及共享目录读取语义。
2. 别名必须以其 **alias ID 本身** 出现在当前目录，才进入候选；仅目标型号存在不能证明该别名已公开。反过来，目录只公开别名而隐藏上游目标时，别名仍是合法候选。
3. ID 精确比较，保留大小写和合法前缀。平台推断仅用于图标和分组，不改变真实请求身份。
4. 旧选择与手填模型继续保存在原草稿中。当前目录未确认的值标注“未在当前目录确认”，弹层独立列出“当前配置（保留原值）”；不把旧值伪装成普通实时候选，也不因刷新失败、空目录或账号停用删除它。
5. Claude 原生角色继续可选，`[1m]` 引用保留。原生角色本身不需要出现在 CPA 目录；角色已经映射具体旧型号时，只标记其目标未确认，不移除角色引用。`[1m]` 以完整 ID 优先匹配，也允许由基础 ID 确认模型身份，不将其视为额外静态型号。
6. 刷新成功后复用原弹窗任务重新读取别名定义，避免别名 ID 未变而目标说明过期。只将同一 CPA 服务的别名规则交给页面；外部服务不沿用本机 CPA 元数据。Codex 已有推理强度约束仍保留其同源配置规则，不因候选暂时缺失而被解除。

角色槽、默认模型、子代理及 Pi 等共享选择器统一使用上述投影。没有新增精选列表或名称输入框，原预览、旧配置及未知字段合并规则保持原样。目录仍使用客户端 `/v1/models` 和客户端 key，账号／别名管理仍使用 `/v8/management`，不回退管理密钥。

## 账号启停与并发顺序

- OAuth 账号启停在管理 API 成功后先校验代理与模式来源，再保留原禁用偏好持久化顺序；立即废弃旧目录响应，完成原账号刷新后读取新目录。管理请求失败时不废弃已确认目录。
- API Key 连接的启停、编辑及原页面已有同步入口，在 v8 配置同步成功后触发同一联动；CPA 停止时仍等待下次启动同步，不额外请求目录。
- 原配置 VM 未创建、仪表盘目录从未加载时不主动创建或激活它们。已经展示的目录继续经过各自原提交入口更新。
- 账号联动令牌固定页面身份、请求世代、客户端、URL 与 key。用户已经手动刷新、关闭重开、切换服务或改变 key 后，旧账号回调不能追加读取或覆盖新目录。旧代理／模式响应也不能修改新会话的禁用偏好或错误状态。
- 外部服务不因本地 CPA 账号变更而刷新；多个账号共同提供的模型由 CPA 实时目录决定，不按本地账号清单逐个删模型。
