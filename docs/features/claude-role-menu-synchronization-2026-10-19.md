# Claude 固定角色说明、独立预览与 1M 声明同步

## 业务归属与边界

本轮处理客户端配置业务的展示与生成一致性。`ClaudeConfigurationPlan` 继续提供纯值计划，原 `AgentSetupViewModel` 持有草稿、目录证据、会话和 Task，原配置 actor 持有磁盘合并、备份和提交事务；不增加状态宿主、目录请求或模型容量表。保留未知字段、合法前缀、具体模型账号说明以及全部原有配置键和类型名称。

`ClaudeModelMappingView`、共享模型选择器和子代理选择器只投影同一份原配置。`ClaudeModelPanelPreview` 仍持有原来的折叠和补全／面板分段状态，调整位置不复制状态，不更换保存或后台同步入口。

## 运行配置核对与根因

只读核对用户运行环境时，实际配置中的 Opus 请求目标是 GPT，而已有 `modelPicker` 的 Opus 说明仍为之前的 Gemini；Sonnet 的旧说明也未跟随新目标改变。旧菜单说明不能作为恢复模型映射的依据。

原因是目录接管计划保留了有效角色菜单行，发现角色选择器已经存在后没有补行，也没有更新其 `description`。CLI 按角色环境变量解析实际模型，而菜单读取保留的旧说明，造成“看起来选 Gemini，确认后提示 GPT”的错配。修复在计划内按 `confirmedRequest` 的最终结果重新生成固定角色说明，保留角色选择器、标题和未知扩展；具体模型的账号说明不受影响。预览和配置输出继续使用同一份计划。

相关原生语义见 [Claude 模型配置](https://code.claude.com/docs/en/model-config)：交互式 `/model` 的 Enter 会保存顶层 `model`，但角色实际指向仍由相应的模型映射解析。本轮真实 CLI 回归验证 `--model` 对应角色的 HTTP 请求，没有把启动参数测试宣称为操作过用户交互式终端。

## 1M 的正确表达

- 同一基础型号可以在 Sonnet 中使用普通上下文声明，在 Haiku 中使用 `[1m]`，也可以反过来；两个用途的设置彼此独立。当前用户配置本来存在这种区别，不能按模型名自动统一或猜容量。
- 原 UI 把独立开关改成了“自动识别”标记，但目录只证明请求 ID，不证明容量；模型选择器读取基础 ID 又隐藏了已保存的后缀。本轮恢复每个角色的原生 1M 开关，完整回显 `claudeRequestModel`，直接默认模型回显 `claudeDefaultModelSelector`。
- 普通“跟随角色”的默认开关仍只读并继承该槽。显式 `role[1m]` 仍有自己的覆盖语义，关闭后恢复普通角色继承；不重写角色槽。
- 默认行、子代理角色选项的说明使用完整请求投影。选择器的显式 `role[1m]` 请求说明也合并该后缀。
- 别名选择提交公开 alias，徽标只看实际提交的 alias 是否携带后缀，不能从目标备注推断已开启。CPA 别名摘要仍按基础别名查询；非 Claude 客户端不把 ID 中的 `[1m]` 当作 Claude 上下文声明。
- 徽标提示明确“显式声明”，补齐中文、英文、法文和越南文，不继续引用缺失的“自动识别”本地化键。全局自定义上下文窗口继续独立且默认跟随 CLI。

## 页面位置

模型槽／子代理卡片下面独立显示模型菜单预览，之后才是默认收起的高级参数。预览自身可折叠，沿用原有分段、滚动和 Default 展示；不增加精选列表、名称输入框或新的内部 Tab。高级区保留上下文、压缩及符合原条件时的网关发现开关。

## 定向验证

全部配置使用临时 home、假凭据和离线目录；真实 CLI 请求只发送到本地假网关，不读取用户账号或转发外部模型请求。

- 迁移回归验证交换角色目标后，已有角色说明跟随新请求；保留显式角色 1M、旧标题、菜单／行未知字段及具体账号说明，不改输入草稿。
- 真实 CLI 回归验证 Opus 配置 Gemini 时，生成说明和实际 HTTP `model` 一致，1M 转为请求 beta 声明。
- 同一 Gemini 型号的 Sonnet／Haiku 正反交换 1M，四次真实 CLI 请求分别核对基础 ID、beta 声明和假凭据，验证不会按型号串槽。
- 原生配置页验证首次／重开后一次应用成功、菜单预览在高级区收起时独立展开，预览不改草稿与磁盘。
