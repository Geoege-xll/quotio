# CPA 模型别名与代理模型槽

## 本轮范围

- Claude Code 的默认模型选择收进模型槽区域，区分跟随 Opus、Sonnet、Haiku 角色槽和指定实际模型或别名。
- 跟随角色槽时同时展示实际请求模型，避免把角色名称误认为服务端模型 ID。
- 模型选择支持搜索，保留已保存但暂时不在模型目录中的选择，不自动替换用户配置。
- Codex 的默认模型与原生思考强度集中放在模型槽区域。
- 本地代理设置增加高级设置中的模型别名入口，代理配置弹窗提供同一管理界面的快捷入口。
- 界面沿用 QuotioTheme、胶囊控件、内嵌卡片和现有弹窗布局规则。

模型别名不是 Quotio 独立维护的默认值系统。OAuth 别名保存到 CPA 的 `oauth-model-alias`，API 来源别名复制对应来源的模型配置，思考强度写入 CPA 的 `payload.override`。

## 配置归属与交互

Claude Code 的角色槽和默认模型仍属于客户端配置。选择某个 CPA 别名，只是让客户端使用该别名发起请求，不应再从客户端生成另一份相互竞争的别名策略。

Codex 普通模型仍保留原生 `model_reasoning_effort`。当所选别名已绑定服务端思考策略时，界面展示 CPA 策略并隐藏容易产生误解的客户端编辑入口；此前保存的原生配置不会因此被清空。

同名别名存在多个来源且思考策略不一致时，不展示虚假的统一强度，而提示实际强度取决于 CPA 路由。

“不指定”表示不为新别名增加思考强度覆盖规则，并不等价于禁用思考。创建和删除别名影响所有使用该别名的客户端，界面提供共享影响提示与删除确认。

## 模型能力与来源

- 通过业务 API Key 读取 `/v1/models`，不把管理密钥用于模型目录接口。
- OAuth 模型能力来自 CPA 的 `/model-definitions/{channel}`，结合启用的认证来源筛选。
- API 来源保留配置节、提供商索引和模型索引，不根据模型名称或 `owned_by` 猜测修改位置。
- 思考等级优先使用模型声明；仅针对官方实现中具有回退规则的 API 协议使用相同回退等级。
- 某个 OAuth 来源能力加载失败时显示提示，不猜测该来源的等级。

## 保存流程与已知限制

读取完整 `/config.yaml`，使用 SHA-256 保存内容版本。写入前重新读取并比较版本；发现外部修改则要求刷新，避免覆盖已知的并发修改。此机制不是服务端原子事务，无法消除最后一次比较与实际写入之间的竞争窗口。

OAuth 映射变化时，先更新 `/oauth-model-alias`，再写入完整 YAML，使模型注册表及时刷新。如果第二步失败，明确提示可能存在部分保存，要求刷新当前状态后处理，不报告完整成功。

YAML 解析和序列化使用新增的 Yams `6.2.2` 精确版本依赖。保存保留已解析的其他配置字段，但不是原文级编辑：重新序列化会改变排版，并且不保留 YAML 注释。这一点与参考客户端的文本保留能力存在差异。对于依赖手写注释维护的配置，使用前应保留原配置备份。

删除别名时保留原模型。清理思考覆盖规则时保留规则中的其他模型目标；相同别名仍被其他来源使用时，不直接移除其共享策略。
