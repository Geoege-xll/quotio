# CPA v8 设置审计与补充建议

## 本轮已完成的删除

原“设置 → 模型与请求策略 → 额度不足时的行为”展示 `quota-exceeded.switch-project` 和 `switch-preview-model`。上一轮曾按用户选择保留成只读兼容项；本轮用户明确同意删除没有 v8 对应字段的功能，已移除该区块、状态、磁盘专用读取、解码类型、无效搜索词与八个本地化词条。

未主动删除用户文件中的历史字段。`CPAConfigLayout.isMigratedV8` 继续允许官方迁移后保留的 `quota-exceeded`，不会因为旧控件消失而误判文件布局。CPA 的路由与重试仍控制账号故障转移；“切换预览模型”旧开关与 Claude Code 的 `/model` 面板预览无关。

用户随后授权首轮五项升级，已完成下表中的首轮能力；其余进阶清单仍为后续建议。详细实施与验证见 [首轮升级记录](cpa-v8-first-round-settings-2026-10-14.md)。

## 配置写入与界面原则

1. 沿用现有分类，不增加内部 Tab；常用项少量常显，数值及复杂规则放在默认收起的高级区域。
2. 新增设置使用 v8 节点读写和明确的成功确认，不重新引入旧 API，不用整份配置覆盖完成单项编辑。
3. 读取时保留真实 `false`、`0` 和空集合；不要把模板推荐值当成文件缺省的运行值。重试缺省仍按上一轮验证的 0／0 呈现。
4. 保留未编辑字段、原有账号、密钥、注释与历史统计。列表字段必须整体替换时，先合并已有值，再精确变更目标条目。
5. 权重与优先级不能混用：权重决定加权轮询分配比例，优先级参与凭据选择；已经建立的会话绑定有自身优先规则。
6. Home 拥有的 revision 字段不能制作成可编辑设置；本地 Redis RESP 用量输出已禁用，不将队列保留字段展示成 Redis 服务开关。
