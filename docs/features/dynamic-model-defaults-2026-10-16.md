# 配置候选改为动态模型目录

日期：2026-10-16。用户在审计静态型号维护成本后，明确选择动态目录方案；本记录替代此前“非 Pi 页面继续保留静态候选兜底”的后续维护要求。前一次静态清理及其构建结果保留为历史记录，不再代表当前默认行为。

## 业务归属与边界

- `Shared/ModelManagement` 保留目录解析、候选映射及 Copilot 可用性证据筛选；删除 `AvailableModel.allModels` 静态清单。`AvailableModel` 类型、编码与 Claude 原生角色表不变。
- `Infrastructure/Networking/ModelCatalogClient` 仍负责无状态传输，配置写入仍由原 `AgentConfigurationService` actor 负责。
- `BusinessModules/AgentConfiguration/AgentSetupViewModel` 继续持有目录和表单状态、原回填 Task；新增的请求世代及只读加载说明仍归该实例。不增加后台模型轮询、全局目录缓存或 Task 宿主，不修改 QuotaViewModel。
- `CustomProviderSheet` 只展示、搜索实际取得的完整目录，取消独立热门 ID 白名单。自定义别名、历史 ID 和接口返回顺序不被白名单过滤；页面沿用原有排序。

## 默认与失败行为

1. Claude 新配置继续使用 `opus`、`sonnet`、`haiku` 原生角色，Fable 保持原有可选映射；不把当前官方型号写进默认槽。旧自定义名称、菜单和子代理配置保留。
2. Codex 新配置没有具体型号默认值，用户从当前服务目录选择，或在现有选择器中手动输入。目录第一项不能自动被认定为适用于 Codex 的默认模型。未选择时，页面和生成器都阻止写出空 `model`；恢复非代理默认模式不受该校验影响。
3. OpenCode、Factory Droid、Pi 的新草稿不再继承 Claude 角色槽。前两者以当前服务返回的模型生成目录；Pi 的保存前实时查证和双文件回滚保持原样。
4. 成功的空目录如实显示为空；失败显示说明和重试入口。目录请求不修改模型槽，旧配置、自定义或手填模型即使不在返回列表中也保留。
5. OpenCode 和 Factory 的完整已保存模型不位于角色槽。目录缺失且无显式槽时，生成器分别沿用原 `provider.quotio.models` 和 `custom_models`，保留全部模型及其能力、显示名和未知元数据；Factory 只更新本轮连接字段。没有任何模型依据的首次配置拒绝保存，不生成假目录。
6. 每次加载清空旧候选，防止上一服务目录被当作本次可用模型；已有选择保存在原配置中。提交须通过请求世代、客户端、URL、密钥及取消校验。关闭重开或并行刷新后，旧响应不能覆盖新目录或结束新请求的加载状态。`resetSheetState` 不失效正在启动的目录请求。
7. 目录接口未返回的能力元数据不伪装为动态结果；本轮撤回了新加的具体型号能力对照表。OpenCode 的既有家族能力生成规则保持兼容，后续如需改进，应独立按能力证据设计。

## CPA v8 与客户端 v1 的区别

CPA **管理接口**使用 `/v8/management/...`，账号、授权和运维继续遵循 v8。[官方管理文档](https://help.router-for.me/cn/management/apiv8.html)

CPA **客户端兼容接口**仍使用 `/v1` 基址，读取模型为 `GET /v1/models`。官方 [Codex](https://help.router-for.me/cn/agent-client/codex.html) 和 [OpenCode](https://help.router-for.me/cn/agent-client/opencode.html) 示例均使用 `/v1`；不能机械改为 `/v8/models`。客户端目录必须使用客户端 API key；两个真实弹窗入口已取消 managementKey 回退，统一读取入口对空客户端密钥不发送请求。密钥稍后由原流程加载后，重试仅补入仍为空的草稿，明确已有 key 不覆盖。页面与生成器同时阻止代理模式缺 key 时写出空认证，恢复非代理默认模式不受限制。

官方厂商也有模型目录接口，例如 [OpenAI List models](https://developers.openai.com/api/reference/resources/models/methods/list)、[Claude List Models](https://platform.claude.com/docs/en/api/models/list)。但公开厂商全集不等于本机代理实际路由集合；本应用优先使用用户当前服务的目录，自定义提供商仍沿原协议端点取数，不额外要求用户配置各家官方密钥。

## 兼容保留与本轮清理

## 追加审计：首次配置、重试及旧配置合并

日期：2026-10-16。按用户后续授权继续核对真实表单、保存服务与各客户端目录失败后的重试。不调整业务归属、类型名称、private(set)、原状态或 Task 所有权；所有改动仍位于原配置业务、传输与配置服务。Pi 仅注入默认仍读取共享服务的只读目录闭包，以便离线覆盖保存前失败和再次提交；原查证、安装、备份、双文件提交／回滚顺序未改变。

### 已修复的问题

- **首次目录尚未返回就可提交。** OpenCode／Factory 的表单回填结束早于模型目录读取，空模型提交会进入失败结果页。统一配置校验现在覆盖目录加载期，按钮和直接调用 apply 都会等待；失败结果页增加“重试”，仅清除结果与错误，保留原草稿、模型和设置，不重新回填磁盘。
- **预览把失败当作仍在生成。** 手动预览现在明确展示已结束的生成错误；认证和地址变化也触发重建。客户端 key 后到达、而目录仍为 `[] → []` 时，旧文件中足够生成的配置能正常显示，避免一直转圈。
- **表单呈现重置回填模式。** `resetSheetState` 不再把已回填的非代理默认模式改回 proxy；初始模式继续由原启动入口设置，磁盘读取负责恢复。
- **目录成功后仍可能丢旧配置。** OpenCode 现在始终保留原 managed 模型、同 ID 的能力和显示元数据、未知 provider/options 字段，并补入新目录及明确选择的模型。Factory 保留根配置和已有顺序，同服务模型只更新连接认证；新 ID 去重追加，其他服务的记录和凭据不被改接到 CPA。空目录和失败也遵循相同保留边界。
- **初始空白文件与损坏文件需区分。** 两类客户端均支持零字节／纯空白文件首次写入，OpenCode 沿用原 JSONC 编辑器的契约；有实际内容但格式无效时拒绝覆盖。自动保存先备份；Factory 复用防重名备份并原子写入，备份失败不继续。
- **读取与生成地址边界。** 模型请求按 URL path 添加 `/models`，兼容末尾斜杠、部署前缀和查询参数。生成器仅移除末尾 `/v1` 版本段，避免全局替换破坏 `https://v1.example.com/...` 的主机名或中间路径。
- **旧调用与连接探测绕过。** 已取消的加载在任何写入之前结束，不能清空新页面目录或失效新请求。“测试连接”同样在 key 缺失时就结束，不发送空 Bearer，更不回退管理密钥。

## 追加审计：并发与配置会话隔离

日期：2026-10-16。核对快速切换客户端、同客户端关闭重开、连续刷新及迟到保存／恢复结果。原请求世代能够隔离已经启动的目录请求，但不足以区分尚未执行的旧页面回调，也未完整覆盖保存、连接测试和恢复后的回填。因此本次在原业务内补齐操作身份，不拆分状态或任务宿主。

### 修复与保留边界

- **页面身份从发起时冻结。** 原 `AgentSetupViewModel` 持有只读配置会话标识；两个真实页面入口和配置弹窗向下传递同一不可变身份。同一客户端使用相同 URL／key 关闭重开，也属于不同会话。旧页面的刷新、别名窗口关闭、预览、重试、备份操作及消失回调，在任何目录或草稿写入之前检查身份，不能取得新页面的请求世代或清除新页面。
- **目录与连接请求分别校验所属轮次。** 原目录请求世代保留，并与会话、客户端、地址、密钥和取消状态共同校验。连续刷新或连接测试乱序完成时，仅当前请求能够提交结果或释放自己的加载标记；当前操作被取消后仍能正常收尾，旧操作的 `defer` 不释放新操作。
- **保存使用发起时的配置快照。** 模式、存储目标、Shell 和模型目录在原保存入口冻结，防止挂起后使用新页面设置继续执行。已开始的文件、Shell 和检测步骤按原顺序完整完成；返回的成功、错误和收尾仅影响所属会话及保存操作，不能回写新表单。状态与原回填 Task 仍归同一 VM，未新增后台任务。
- **备份恢复固定发起客户端。** 实际恢复仍由原配置服务执行；恢复后的配置读取和草稿提交同时校验会话、读取世代及发起客户端。旧恢复结果不能改为读取新选择的客户端，也不能覆盖同客户端重新打开后的草稿。删除备份的列表、错误及收尾同样按会话提交。
- **Pi 自动保存防止真实文件事务交错。** 原 `AgentConfigurationService` actor 私有持有自动保存互斥，覆盖目录查证、安装、备份及双文件提交／回滚。首轮尚未完成时，再次自动保存或恢复 Pi 备份明确提示稍后重试；拒绝的新调用不能释放旧锁。手动预览不取得或释放此锁，已开始事务不被中途打断。互斥作用于原服务实例，生产入口继续复用原 VM 和配置服务。
