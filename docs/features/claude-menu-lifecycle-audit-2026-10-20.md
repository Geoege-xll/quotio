# Claude 菜单跨账号、目录与 CLI 保存的生命周期审计

日期：2026-10-20。范围：在上一轮名称／来源统一的基础上，复核账号启停、目录刷新及真实 `/model` 保存回读；发现问题直接修复，不改变现有备份策略。

## 问题与修复

1. **自动友好名称写盘后失去自动身份。** 原生成器把非空标题当成用户名称，第二次读取后端改名时仍显示首次名称。现有根托管信息新增版本化 `projection`，只对仍精确等于上次生成结果的标题恢复自动输入，再由统一计划根据当前目录生成。用户外部修改的标题、无来源记录的历史自定义标题保持原值。
2. **目录推导的 1M 写盘后变成固定开启。** 旧读取把任何 `[1m]` 都当成历史显式选择，目录降为普通窗口后，角色、Default、子代理及追加菜单继续输出旧后缀。现在记录自动上下文的精确选择器绑定，回读恢复自动输入；新目录重新决定是否输出后缀。CLI 从自动菜单保存为 Default 时也沿用同一规则。
3. **同型号不同用途的旧声明需要独立持久化。** 明确开启的 Default 不能被同名自动菜单吸收；角色明确 false 写成裸 ID 后，也不能回读成未指定并重新自动开启。`default-explicit` 和 `normal-<role>` 绑定只作用于仍匹配的最终选择器，分别保留这些已有独立声明，不把所有裸 ID 都判为显式 false。
4. **同文件名凭据的来源可能查询错误。** 官方 CPA v8 的模型查询参数同时匹配 ID 与文件名，按文件名查询两个不同账号可能重复读取首个账号，再误报账号池。改为使用 API 原始唯一 ID，并检查该查询值在完整响应的 ID／文件名域是否有歧义；歧义或部分失败时不声称已确认单账号或账号池，不使用本地去重生成的合成 ID。
5. **后台同步未覆盖整个来源与提交周期。** 后台任务在首次挂起前固定管理客户端，每次挂起后复核；客户端替换、初始化、停止以及原启动协调器真正执行时同步推进现有模型世代，撤销已经排队的旧提交许可。停止先撤销许可，再执行运行会话变化和停止副作用。不能仅在配置 actor 写完后隐藏旧结果。
6. **恢复可用与新增账号的部分路径遗漏菜单刷新。** 单个／批量冷却重置、认证文件导入、通用 OAuth 成功、Copilot／Kiro 的实际授权成功分支、Kiro 导入及 Vertex 导入复用既有“失效模型→刷新账号→刷新目录／同步受管菜单”链路。失败操作不取得新的模型刷新；原轮询不会每一轮都额外请求模型，导入仍成功后只刷新一次，并保留原来源及会话守卫。

官方查询契约核对：[CPA v8.0.28 auth_files.go](https://github.com/router-for-me/CLIProxyAPI/blob/v8.0.28/internal/api/handlers/management/auth_files.go#L315-L340)。模型可用集合仍以客户端认证的 `/v1/models` 为准，v8 凭据模型信息只补充展示来源，不新增型号或改变账号路由。

## 协议与未知字段

- `projection` 位于已有 `quotioClaudeCatalog` 根命名空间，不写进 CLI 会规范化的菜单嵌套对象；只保存生成的模型选择器、名称和自动／显式来源绑定，不保存客户端密钥或额外账号凭据。
- 恢复自动输入需要当前连接指纹匹配，并且磁盘当前值仍精确匹配已生成值。Messages 基址先转换为模型目录基址后比较指纹，保留部署前缀。
- 原 JSON 顶层、菜单层、条目及根托管对象的未知字段继续无损合并。恢复官方仅撤下已知投影成员，未知投影字段与未来上下文成员保留为无归属残壳；再次应用允许合并该残壳，但不会把它读作有效自动凭证。
- 未来版本或无法解释的已知投影结构在备份、写盘之前拒绝，保留原文件，不用猜测语义覆盖。
- 非受管旧服务调用不执行自动输入恢复，原有菜单文字及上下文继续透传。
- 当前备份命名、原字节保存、恢复入口、写入回执、Shell 失败回滚、原子提交及相同输出免写入规则不变。

## 业务归属与所有权

`ClaudeCatalogProjection` 与原 `ClaudeCatalogOwnership` 同文件维护，共同负责托管磁盘协议，不为减少行数拆分。读取与提交仍由原 `AgentConfigurationService` actor 负责；目录、请求世代与提交许可仍由原 `AgentSetupViewModel` 持有。

账号变更桥接及生命周期调用仍属于原 `QuotaViewModel` 及已有扩展。新增方法仅顺序复用已有刷新与失效入口，不增加存储属性、Task、后台轮询或单例，不开放私有 setter，不改变授权／导入目标固定和成功后刷新顺序。仅 Debug 的只读许可观察复用已有对象，用于验证替换客户端时同步撤销许可。
